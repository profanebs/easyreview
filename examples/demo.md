# 摘要
- 这是泛用版的体验页，布局和审阅操作沿用原版。
- 「选项」里可以切换浅色宣纸、深色水墨；试着给任务划结论，再写一条批注。
- 此页是演练文档，任何测试结论都不构成真实项目的批准。

# 这是啥
这一页把同一份 Markdown 交给 Codex、OpenCode、Kiro 或 Cursor 审阅。程序只在本机运行；保存后的反馈留在输出目录。

# 因为啥
让你熟悉的界面保留原位，用纸色、墨色和宋体降低视觉噪声。代码与按钮仍用各自清晰的字体，不靠装饰表达任务状态。

# 这波整了啥

## T1: 试试任务三态和批注

**这是啥**: 左栏「计划」中的勾表示放行，叉表示要改；再点同一按钮即可撤回。正文选择一句话或切到点选模式，写一句批注。

**因为啥**: 没看过、看过但要改、已经放行是三种不同结论。原来的语义继续保留，不能把沉默当成同意。

**会咋坏**: 在多个浏览器或端口间切换时，未保存的草稿不会自动迁移。助手重启后的旧页无法用旧 token 保存。

**咋修复**: 在当前页保存后读取输出目录中的反馈文件。助手重启就重新渲染；旧页还可以复制反馈。

## T2: 试试表格、代码和图表

**这是啥**: 表格、代码、公式、图表沿用原来的渲染器。深浅切换应同时影响整个页面，包括问答和弹层。

**因为啥**: 字体各司其职：正文宋体、按钮黑体、代码等宽。墨色虽柔和，正文和关键提示仍需清楚。

**会咋坏**: 如果某段 Markdown 写错语法，原渲染器会显示原始文本。极小屏幕会启用原来的折叠视图。

**咋修复**: 先检查语法；窄屏通过工具入口打开目录和批注，仍然可以完成审阅。
